Elastic 推出 ES|QL Data Federation：直接查询 S3 上的开放格式

来源： Elastic 官方博客
摘要： Elastic 宣布 ES|QL Data Federation 进入技术预览：用 ES|QL 的 FROM 语法直接查询 Amazon S3 上的 Parquet、NDJSON、CSV、TSV 文件（含 gzip、zstd、snappy 压缩），查询时推断 schema，无需摄取、无需第二查询引擎，Kibana 看板与检测规则照常工作。该能力现已在 Elastic Cloud Serverless 可用，预计 12 月初随 Elasticsearch 9.6 进入 Cloud Hosted 与自管部署。官方路线图还包括 Google Cloud Storage、Azure Blob、数据湖目录，以及 Redshift、Snowflake 等数仓与数据库。
为什么对数据平台重要： 过去分析、安全与合规场景要查对象存储里的归档数据，必须在 Elasticsearch 之外另立 Athena、Trino、Spark 等第二引擎并手工对账；现在同一条 ES|QL、同一套权限与看板可同时覆盖索引数据与开放格式归档，官方还给出谓词下推、TopN 下推等针对外部数据的性能工程。搜索引擎正式加入「查询引擎伸向对象存储开放格式」的阵营，以就地查询替代数据复制进一步成为跨引擎的默认形态。

Aurora serverless MySQL 容量上限提升至 384 ACU

来源： AWS What's New
摘要： AWS 宣布 Aurora serverless（MySQL 兼容版）单节点最大容量从 256 ACU 提升至 384 ACU（提升 50%，约 768 GiB 内存），要求 Aurora MySQL 3.14 或 8.4.10 及以上内核并运行在 Platform Version 4；旧平台版本集群需通过维护操作升级，已在 Platform Version 4 上的集群修改配置即可、无停机。官方点名智能体应用突发式、长空闲、流量不可预测的负载为主要适配场景。
对数据平台的影响： 弹性上限抬高让此前因 256 ACU 天花板被迫迁往预置实例的大规格负载可以留在 scale-to-zero 模型，兼顾峰谷成本；同时按 ACU 实际用量计费，失控查询或缺失索引的账单风险同步放大，容量上限需要与 ServerlessDatabaseCapacity、ACUUtilization 监控告警一起调整。
