Databricks 发布 Agent Memory：智能体记忆层进入平台托管阶段

来源： Databricks 官方博客
摘要： Databricks 10 月 20 日在 Agent Bricks 智能体开发平台推出 Agent Memory，当前为 Beta，基于自研 MemCurrent 记忆架构并运行在 Lakebase 托管 Postgres 上，包含托管会话、托管记忆与记忆管线三部分：会话按框架原生格式记录消息、工具调用与结果，记忆层保存画像、偏好、领域知识与工作流并在会话开始时载入索引、过程中用关键词与语义混合检索，后台记忆管线按需或定时把会话提炼为长期记忆、去重并用新对话覆盖被推翻的事实。官方内部基准显示，接入该记忆架构后智能体在企业数据任务上的通过率约为无记忆时的三倍，词元消耗减少 31%；对照方案中，把完整历史全量回放进上下文在开源记忆基准上每个问题所需输入词元约为设计良好记忆的 12 倍，且在最长的历史上得分反而更差。官方给出的单一会话示例中，无记忆时智能体用了 11 次工具调用、8 个子智能体、近 6 分钟回答某产品头部客户问题，工作流存入记忆后，关联追问降至 2 次工具调用、41 秒。同一架构已在自然语言业务问答产品 Genie 上运行。
为什么对数据平台重要： 记忆从开发者自建组件变成平台托管能力，抽取、去重、检索与访问控制的责任边界被重新划定：过去这类工作落在对象存储或向量库上，如今由数据平台的托管数据库承接，记忆的时效、冲突与可追溯性随之进入平台治理范围。对平台团队而言，智能体状态成为一类需要独立容量规划、备份与权限管理的新数据资产；自建记忆栈在托管方案面前少了成本优势，但多引擎部署的互操作性要求也随之上升，跨框架记忆迁移成本成为新的选型变量。

Snowflake Online Feature Store 正式可用：在线特征与模型服务并入同一仓库

来源： Snowflake Blog
摘要： Snowflake 10 月 20 日宣布 Online Feature Store 正式可用，与在线模型服务一同面向任何生产场景开放，构建在 Snowflake Postgres 之上：事件同步写入托管的 Postgres 服务层，配合原生连接池与按 schema 的单租户隔离提供低延迟读取。官方给出的典型指标为低延迟特征读取 P50 低于 10 毫秒、流式特征端到端新鲜度 P50 低于 200 毫秒、从模型注册表调用模型的推理延迟低于 100 毫秒，无状态 REST 端点负载测试超过 40,000 QPS；模型服务部署在 Snowpark Container Services 上，通过 CPU 密集的请求处理与 GPU 密集的模型执行解耦、动态批处理与请求流水线提升吞吐，使特征获取与模型推理在一次网络往返内完成。厂商基准称在线特征服务相较 Databricks 延迟低 2.5 倍、QPS 高 7 倍，实时模型推理相较 SageMaker 与 Databricks 快 2 至 5 倍、成本最多低 3 倍。Neon 的迁移案例显示其 P99 特征延迟从约 140 毫秒降到约 72 毫秒、反欺诈引擎可用性从 99.7% 提升到 99.9%，数据为厂商与客户自述。
为什么对数据平台重要： 特征存储此前通常是仓库之外的独立系统，需要额外维护一份在线副本；把它建在仓库自己的 Postgres 上并与模型服务同批转正，训练侧数据、在线特征与推理端点共享同一套治理与访问控制，特征新鲜度与模型版本的对应关系不再靠跨系统同步维护。对数据平台的影响不止于延迟数字：在线副本的容量与成本从独立预算项变回仓库内的资源规划，实时特征的回溯与一致性审计也随之在平台内完成。需注意所有对比数字均来自厂商基准与客户案例，选型时应以自有负载复测。

Gartner 发布 2027 十大战略技术趋势：上下文平台与智能体身份进入榜单

来源： Gartner 官方新闻稿
摘要： Gartner 10 月 20 日在年度 IT 大会上发布 2027 年十大战略技术趋势，由高级杰出副总裁分析师 Gene Alvarez 发布，他指出当前的系统性问题在于 AI 运行在架构真空中，产出的软件快于人类审查速度，因而产生失控的凭据路径并把流程绑定到单一供应商垄断。榜单十项为：大型量化模型、语音推理模型、世界模型、AI 上下文平台、智能体编码框架、AI 智能体身份、自治暴露修复、主权技术、一次性应用、湿件即服务。其中与数据平台直接相关的三项：AI 上下文平台指为智能体提供解读输入所需的上下文知识，厂商称缺少专用上下文层会带来过度授权的智能体、合规失效、低信任与词元过度消耗等运营风险，预测 2027 年优先在 AI 就绪数据上经营语义的组织，其智能体准确率最多提升 80%、成本最多降低 60%；AI 智能体身份预测到 2028 年 25% 的企业安全入侵将源于智能体滥用，原因指向未受管理的机器权限与遗留凭据实践；主权技术指在技术与法律上为关键供应商提供现实退出路径的硬件、软件、数据库与模型组合，预测到 2030 年超过 75% 的非美国组织采纳数字主权战略。
为什么对数据平台重要： 榜单把「上下文平台」与「智能体身份」抬为独立技术趋势，等于把数据目录、血缘与权限体系从治理附属品确认为与计算和推理同级的架构层：这直接决定平台是否要按智能体身份而非人类用户建模权限，静态凭据在智能体场景下的失效也会成为基础设施改造的硬需求。主权技术被定义为包含数据库层的组合，意味着数据主权不再是机房与合规文本问题，而是要在选型阶段就具备跨供应商的退出路径。两大趋势同榜意味着平台选型的评估口径正在从功能清单转向语义供给能力与身份治理成熟度。

AWS Clean Rooms 支持 Databricks 数据源：协作查询不必再经对象存储中转

来源： AWS What's New
摘要： AWS 10 月 20 日宣布 Clean Rooms 新增 Databricks 作为数据源，协作成员及其合作伙伴可直接在协作体内查询通过 Delta Sharing 共享的 Databricks 表，无需移动或暴露源数据。此前使用 Databricks 数据的成员必须先导出或复制到 Amazon S3 才能在协作中作为表使用，这既增加了管道工作，也多出一份需要治理的数据副本；现在成员只需提供工作区地址、schema 与表名以及一个 Delta Sharing 共享链接即可注册该表并对协作方开放。官方给出的场景是：管理客户数据的零售商可在 Clean Rooms 中与媒体合作方开展营销活动衡量，直接对 Databricks 数据运行获批分析，无需先构建并维护一条到 S3 的导出链路。Databricks 加入后，Clean Rooms 支持的数据源包括 AWS Glue、Snowflake 与 Amazon Athena。
对数据平台的影响： 隐私计算协作的接入成本从「先搬一份数据」降为「注册一次表」，湖仓原生数据与云内数据源的隔离策略被拉齐到同一套机制里，跨组织协作不再需要为每家合作方单独维护导出管道。对数据平台团队而言，共享协议层正在成为数据交付的默认接口，数据副本治理清单可以收缩一档；同时需留意 Delta Sharing 共享链接的权限粒度与有效期管理会成为新的暴露面，协作侧的安全评估不能只看 Clean Rooms 本身的策略配置。

Couchbase 扩展 AI Data Plane：托管记忆与托管 MCP 服务落到 AWS

来源： PR Newswire 官方发布
摘要： Couchbase 10 月 20 日宣布 AI Data Plane 扩展并转为正式可用，新增原生 Amazon Bedrock 集成与语义缓存，并把今年六月以自管形式提供的托管 Agent Memory 与托管 MCP Server 全部转为全托管、运行在 AWS 上；Operational Insights 内建向量搜索。官方给出的收益数字为：语义缓存减少 40% 至 60% 的模型调用，Agent Memory 在 LoCoMo 基准上少用 33% 至 45% 的词元、提示词缩短 70%，超过半数的生产部署总拥有成本下降超过 50%。
对数据平台的影响： 文档数据库把记忆、协议服务与语义缓存打包进自己的托管数据平面，运营型数据的读写路径与智能体的状态管理合到一套产品里，企业不必再为智能体另立一套记忆存储与协议接入层；缓存与记忆带来的调用与词元下降，直接改变运行智能体的单位成本结构，可用于重估把交互式文档数据交给该类数据库的边界。需注意上述百分比全部来自厂商自测与客户案例，LoCoMo 等公开基准的选取与负载设置都会显著影响结果，采购评估应要求在自有负载上复测。

AWS 走查智能体语义层：AtScale 经三协议暴露模型，单引擎约束写进架构

来源： AWS Machine Learning Blog
摘要： AWS 10 月 20 日发布一篇走查，说明如何在 Amazon Bedrock AgentCore 上用 AtScale 构建面向智能体的语义层。语义模型以开放的 YAML 规范描述，对象拆分为独立文件并纳入 Git 版本管理，Git diff 成为模型变更的权威记录；同一模型同时通过 SQL、XMLA 与 MCP 三种协议暴露，分别面向 JDBC 客户端与笔记本、Excel 与 Power BI、以及智能体客户端，目标是让智能体经 MCP 得到的指标值与 Excel 透视表经 XMLA 得到的数值完全一致。行级安全与视角是模型对象而非提示词内容：查询规划阶段先验证调用方令牌、把用户解析为角色、套用该角色的视角，再应用行级安全，最后把原生 SQL 下推到 Amazon Redshift，身份经企业 IdP、网关、运行时与 OAuth 令牌链路传递。执行约束被明确写为一次查询只落在一个仓库引擎，不支持查询时跨引擎实时联邦，跨引擎数据需在上游整合或改用仓库自身的联邦能力。聚合管理器按跨消费者的实际查询模式在仓库内物化汇总表，后续匹配查询被透明改写为读取汇总表。
对数据平台的影响： 这条走查把智能体语义层的三个争议点摆成了可检查的实现约束：安全定义落在模型层而非提示词，才能对智能体与人类一视同仁；一份模型多协议暴露，才能避免每个消费端各写一套指标逻辑；单引擎执行与查询时跨引擎联邦的取舍，则决定语义层能否直接接在多仓库并存的现实架构上。走查同时说明语义层正在成为智能体与仓库之间的必经中介层，模型版本管理、血缘与改写审计的需求会从工具内部溢出到平台工程排期。

Gartner 2027 CEO 调研：四成 CEO 无法向利益相关方证明 AI 财务回报

来源： Gartner 官方新闻稿
核心观点： Gartner 10 月 20 日发布 2027 年 CEO 调研，2026 年 4 月至 5 月间执行，样本为 203 名全球 CEO 与高级业务管理者。44% 的 CEO 难以向利益相关方证明 AI 带来的财务回报；75% 计划增加技术投资，62% 把营收与业务增长列为首要战略优先级；80% 的 CEO 认为技术已成为战略本身。对 2027 年的扰动预期中，93% 预期经济波动对战略目标有高或中等影响，79% 预期持续冲突、77% 预期 AI 工业化带来同等程度影响，而相应的高准备度分别只有 24%、11% 与 20%。就加速财务回报的「强力动作」，63% 选择彻底重构运营模式，52% 选择把 AI 智能体激进地部署为员工，47% 选择通过重大业务重组释放或重新配置资本。杰出副总裁分析师 David Furlonger 的判断是 AI 价值问题无法靠往既有工作方式上叠加更多 AI 解决，CEO 需要的是技术带来的战略自由，即更快进入市场、重塑产品、重构运营并应对颠覆的能力；他同时提示 CIO 若停留在下游实施者位置，将被排除在 increasingly 定义竞争优势的决策之外。
映射到数据平台的判断： 调研把「AI 投入是否成立」的裁判权明确交给了企业决策层，而 44% 的举证困难意味着数据平台团队将直接承接单位用例经济性的举证任务：交付形态需要能落到单位成本、决策速度与业务结果这类可审计口径上，否则难以通过 CEO 层面的复核。同时 63% 选择重构运营模式、52% 选择把智能体部署为员工，意味着数据与治理流程本身要按可被智能体调用与审计的标准重写，而不只是给人用；平台能力的计价单位可能因此从席位与作业数转向被智能体消费的调用与决策量。

Gartner Day 2 提出智能体治理方法论：分层护栏栈与事故热点自查

来源： Gartner 官方新闻稿
核心观点： Gartner 副总裁分析师 Svetlana Sicular 在 10 月 20 日大会第二天给出智能体治理的具体方法论，核心是一张分层护栏栈与一组动作：设定治理将随系统规模迭代演进的预期；停止忽视人机新交互以及数据与上下文盲区这类事故热点；开始收集证据以备外部审查；构建含多重监督机制的分层护栏栈，并按自治程度调整监督强度。同期分析师 Mary Mesaglio 提出 AI 智能体正在经历「现实检验」，落地的甜区在可靠性与安全性同时满足自主性之间；AI 价值差距实质是 AI 风险差距，成本是规模化最大的战术风险；软件即服务正转向无头工具并更深地嵌入技术栈。
映射到数据平台的判断： 方法论把「数据与上下文盲区」直接列为智能体事故热点，等于确认数据平台是治理栈中承担证据与护栏落地的关键层：权限、审计、上下文正确性这些原本属于数据工程范畴的能力，会成为智能体治理能否通过外部审查的举证材料。分层护栏与按自治程度调节监督强度的思路，也提示数据平台的风险分级不能只按数据敏感度划分，需增加按智能体自治等级划分的维度。

【降级】Snowflake Horizon Context 进入公开预览：18 个元数据连接器与描述血缘传播

来源： Snowflake 官方 Release Notes
为什么值得继续看： 该能力的功能更新实际发布于 10 月 12 日，10 月 20 日厂商博客为同一批能力的宣传性复述，按时效规则降级收录。Horizon Context 是 Horizon Catalog 内扩展到 Snowflake 之外的治理上下文层，本次公开预览包含三项能力：面向 18 个来源的元数据连接器，覆盖九个商业智能系统与八个数据库并含 dbt 管道工具，可跨平台浏览检索外部资产、追踪列级血缘；外部元数据管理，可直接在目录中编辑 Power BI 与 Tableau 仪表盘的描述、标签与联系人；元数据只读编辑权限，新增 APPLY COMMENT 权限让数据管理员编辑描述而不必获得 MODIFY 或 OWNERSHIP，且不要求 ACCOUNTADMIN 角色。列描述传播按血缘把描述带到值未改变的下游列，值被变换、合并或聚合时停止传播，也不覆盖下游直接编写的描述，目录中可区分传播描述与用户撰写描述。该能力在 AWS 与 Azure 商业区域可用，不含政府区域与中国区。
需要等待什么信号确认： 十八个连接器的实际接入稳定性与各源元数据采集的完整度，描述传播在多跳转换下的准确性，以及公开预览转正式可用时新增或变更的能力范围。

【降级】Snowflake 工程博客披露智能体可观测性接口的消融结果

来源： Snowflake Engineering Blog
为什么值得继续看： 该文发布于 10 月 19 日，按窗口规则降级收录。文中以智能体在可观测性问题上的通过率为指标做消融：仅提供结果查询接口时通过率为 7.8%，补入基础定位接口后升至 26.2%，再补入领域接口后达 69.0%；单独去掉领域运维接口退回 26.2%，去掉路径到数据映射为 51.2%，去掉实体解析为 54.8%，去掉可组合性为 65.9%。相对基线延迟与词元消耗各下降 58%，工具调用从 15 次降至 6 次；评测用 Cortex 的 gpt-5.4 作裁判，每种配置 168 次试验，并在持续集成中设置质量门禁。
需要等待什么信号确认： 该接口设计是否成为 Snowflake 智能体运维产品的正式能力，门禁指标能否在客户真实负载上复现，以及领域接口与实体解析所需的元数据投入是否具备普遍性。

【降级】腾讯云把智能问答搜索能力通过接口对外开放

来源： 腾讯云 API 文档
为什么值得继续看： 腾讯云 10 月 20 日宣布将智能问答搜索能力通过腾讯云对外开放，提供技能、模型上下文协议与接口三种接入方式，每月提供 2000 次免费调用额度。官方称该服务为千亿级索引、日均调用数亿次、支撑 50 余项腾讯自有业务，覆盖 13 个垂直行业的 157 个权威信源，全网收录覆盖率 96%；检索侧采用倒排、向量与融合三类索引融合，底层索引检索平均 8 毫秒，排序模型推理经优化从 149 毫秒降至 30 毫秒。该能力在定位上属应用层搜索服务而非数据平台产品，与本期主题的映射偏弱，故降级收录。
需要等待什么信号确认： 该服务是否进一步开放索引构建与检索链路的可观测性、是否提供面向企业数据源的自定义索引接入能力，以及免费额度之后的计费口径与并发限制。
