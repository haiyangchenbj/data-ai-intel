Databricks 多语句事务正式 GA：开放表格式上首次原生支持跨表事务

来源： Databricks Blog
摘要： Databricks 10 月 16 日宣布多语句事务正式可用，覆盖 Unity Catalog 托管的 Delta Lake 与 Apache Iceberg 表，官方称其为首个在两类开放表格式上原生支持多语句、多表事务的湖仓架构。开发者可把多步变更作为一个原子单元提交或回滚，并与存储过程、临时表、SQL 脚本组合，事务还能写入流式表；Unity Catalog 行级安全与列掩码在事务读写中继续生效，行级并发让多个事务并行写同一张表的不同行。数据集成商 Fivetran 借此把维度表关闭旧版本与写入新版本合并为一次原子提交，删掉一整类一致性修复代码；健康科技公司 Accolade 每天在生产环境运行约 1700 笔事务处理理赔数据，无需为事务保证再架一套独立数仓。
为什么对数据平台重要： 跨表事务保证是传统数仓守住关键负载的最后一道护城河，此前迁移湖仓的组织要么放弃多表原子性、要么保留并行仓库承担双份数据与治理。Databricks 把这道能力做进开放表格式并以行级并发承压，仓库级工作负载向湖仓迁移的最后一个技术理由被抽掉，直接改写数仓与湖仓的选型天平，也给仓库形态厂商的开放兼容策略加压。

Google 把 borderless Lakehouse 接进 Gemini，Agent 直连竞对目录数据

来源： Google Cloud Blog
摘要： Google 10 月 15 日详解 borderless Lakehouse 与 Gemini 的新集成（预览版）：数据源经 Lakehouse 目录联邦直接接入 Gemini，业务用户可用自然语言跨云查询记录，智能体用同一份数据完成推理与代码生成，无需移动数据，首批可接 Databricks Unity Catalog 与 Snowflake Horizon。同期一批年初发布的特性转正：跨云互连与跨云缓存、BigQuery 对 Iceberg V3 规范的支持、BigQuery 与托管 Spark 的 Iceberg 表读写互操作、AlloyDB 湖仓联邦、与 AWS Glue 及两家竞对目录的双向目录联邦缓存、Knowledge Catalog 集成、Salesforce/SAP/Workday 与 Confluent Tableflow 零拷贝集成、经 Dataflow 同步 Delta Lake 资产。Google 称客户对 Iceberg 的使用量自 2025 年初以来增至三倍以上，Etsy 用 borderless Lakehouse 统一 3PB 数据、管道查询提速六成。
为什么对数据平台重要： 智能体落地的主要瓶颈从模型能力转向数据可达性，Google 的解法是把自家模型做成横跨各家的数据前门：不搬数据、经目录联邦直连 Unity Catalog 与 Horizon，跨云缓存与专线消除延迟和出口成本。平台竞争的界面随之从存储引擎上移到目录与语义层，谁被接进谁的智能体前门，直接影响平台在智能体时代的数据入口份额。[补录 10-15]

TiDB Cloud 在 SCaiLE 2026 集中发布：Premium 商用计划、BYOC 公测与智能体持久工作区

来源： PingCAP 官方新闻稿
摘要： PingCAP 10 月 15 日在 SCaiLE 2026 大会发布一揽子 TiDB Cloud 更新：TiDB Cloud Premium 计划 11 月正式商用，提供资源隔离、自动扩缩容与私有连接；自带云部署 BYOC 与 TiDB Cloud Filesystem 进入公开预览，后者给智能体一个跨会话持久的文件工作区，保存的代码与上下文在新沙箱中可续用；TiDB Cloud Starter 开放 PostgreSQL 兼容公测。公司同时宣布计划在 2026 年底前开源新一代架构 TiDB X 的核心代码。规模化案例集中展示智能体建库形态：Manus 平台已运行超 150 万个 TiDB Cloud 集群，Moonshot AI 的 Kimi 用 Filesystem 支撑超百万个持久文件系统，Atlassian 把 750 多个 PostgreSQL 集群合并为 16 个 TiDB 集群。
对数据平台的影响： 数据库厂商正把智能体当作一等负载类型设计产品：会话间持久的文件系统、按需建库、自带云部署，都是在把智能体的生命周期管理做进数据层。PostgreSQL 生态兼容让 MySQL 系厂商反向吸收最大开源数据库的开发者群体，TiDB X 开源计划则把托管云的核心架构变成可审视的公共资产，影响国产数据库在智能体场景的选型逻辑。[补录 10-15]

AWS 中国区推出 S3 Files：对象存储桶可直接挂载为文件系统

来源： 亚马逊云科技中国公告
摘要： AWS 10 月 16 日在中国区公告推出 Amazon S3 Files，让 S3 存储桶能以共享文件系统的形式被计算资源直接访问，数据始终留在 S3。该能力构建在 Amazon EFS 之上，维护桶内对象的视图并把文件系统操作转换为高效的 S3 请求，应用无需改代码即可用文件工具读写对象存储；数千个计算资源可同时挂载同一个 S3 文件系统实现跨集群共享，配合缓存提供 TB/s 级聚合读取吞吐，桶内新旧数据无需迁移。基于文件的应用、机器学习数据准备与智能体共享状态等场景无需再在对象存储与文件存储之间复制同步。该能力今年 4 月已在海外区域正式可用，本次为中国区域落地。
对数据平台的影响： 数据湖主体在对象存储上、而基于文件的工具与训练管线要求文件语义，是湖仓架构长期存在的接口断层，通常靠独立文件网关或双写同步弥合。S3 Files 把文件接口做进对象存储本体并保留桶为唯一事实源，省去复制与同步链路，也降低智能体工作流读写湖内数据的工程成本；国内数据平台与对象存储的组合选型可参考这一接口方向。

Snowflake Iceberg v3 表升级与表达式默认值正式可用

来源： Snowflake Release Notes
摘要： Snowflake 10 月 16 日宣布 Apache Iceberg v3 表升级与表达式默认值正式可用。既有 v2 表经 ALTER ICEBERG TABLE 语句原地升级到 v3，保留表名、权限与下游引用，无需重建；默认值、行谱系、删除向量与新数据类型等 v3 特性随之解锁，Snowflake 托管表与经 Iceberg REST 目录管理的外部表均可升级，含目录关联数据库中的表。v3 表新增 SQL 表达式、序列与自增列作为列默认值，可求值为常量的表达式写入 Iceberg 元数据，其余默认值经新参数控制仅对 Snowflake 写入生效；升级为不可逆操作，托管表可在保留期内用 Time Travel 回退 v2。
对数据平台的影响： Iceberg v3 已从规范演进进入主流平台全面落地阶段：Google 同期宣布 BigQuery 支持 V3 规范，Snowflake 把原地升级与表达式默认值做进托管服务。默认值、行谱系与删除向量直接改善行级更新与 schema 演进的工程成本，开放表格式版本升级的迁移摩擦被压到一条语句，平台间兼容性竞争进一步聚焦 v3 特性覆盖度。

Amazon EMR 支持 Spark 作业原生数据质量检查

来源： 亚马逊云科技中国公告
摘要： AWS 10 月 16 日在中国区公告 Amazon EMR 支持 Apache Spark 作业中的原生数据质量检查。EMR Data Quality 由 Amazon Glue 数据质量能力驱动，使用与 Glue 相同的声明式规则语言与 API，在两个引擎上提供一致体验，不额外收费；可在 EC2、EKS 与无服务器部署模式下与 Apache Iceberg、Apache Hudi、Delta Lake 表结合使用。数据工程团队可在坏数据进入下游系统前于作业内联发现质量问题，无需构建维护独立的验证基础设施。
对数据平台的影响： 数据质量验证正从外挂工具链收编为计算引擎内置能力，规则定义在 Glue 与 EMR 间复用意味着质量规则开始跟随表与作业而不是跟随工具。对自建验证层的团队，引擎内置检查改变其在质量工具上的投入方向；对国产引擎厂商，Spark 侧内建质量能力会成为对标清单上的常规项。
