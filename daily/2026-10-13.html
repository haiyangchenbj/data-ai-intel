🔥 今日最重要的3个变化

  1. 语义层正从配置项变成要评审、要版本管理的工程产物
  2. 数据平台的运维与调优正被交给智能体托管
  3. 存储、向量检索与数据管道正在被合并为同一层底座
总判断：数据平台为智能体让路的方式正在变具体：语义定义要能被评审和回滚，运维诊断要能被自然语言唤起，生产数据要能一键克隆出隔离副本。竞争焦点从"功能有多少"转向"智能体能不能安全、可审计地在平台上干活"。

Top Signals

Snowflake 语义视图进入 IDE：Semantic Studio 正式 GA

来源： Snowflake Blog
摘要： Snowflake 宣布 Semantic Studio 正式可用，把语义视图编写从 Snowsight 的单页编辑器搬进 Workspaces，与团队已有的 SQL、Notebook、dbt 项目并列。新版本加入 Snowflake CoCo 深度集成、git 版本管理与体验改进，语义视图成为团队仓库中的一个文件。
为什么对数据平台重要： 语义视图如今被每个智能体和每个 BI 工具读取，一行改动能同时影响全部消费方。把它变成有作者、有理由、可回滚的仓库文件，等于让语义层复用既有的代码评审、评测与 CI/CD 链路，治理位置从运行时前移到交付时。

微软开源 PostgreSQL 运维智能体，把告警变成答案

来源： Microsoft Open Source Blog
摘要： 微软开源博客发布面向 PostgreSQL 运维的数据库智能体，把监控告警、日志与运行状态组织成可理解的结论与处置建议，并在 Microsoft Fabric 的 Database Hub 提供单一面板做可观测。
为什么对数据平台重要： 数据库运维长期依赖专家跨页面、跨命令拼接信息；把这条链路交给智能体，等于把运维知识沉淀为产品能力，也让"智能体托管基础设施日常操作"从概念落到可复用的开源件，直接冲击数据库可观测与运维工具链的形态。

Google Cloud 把多元时序基础模型 TimesFM 3.0 放进 BigQuery

来源： Google Cloud Blog
摘要： Google Cloud 发布 BigQuery TimesFM 3.0（预览），支持多元时间序列预测，用于需求、销量与容量等业务量的预测，官方称其在多个公开预测基准上取得领先。
为什么对数据平台重要： 预测能力从需要单独搭建的数据科学工程，下沉为仓库内可调用的原生能力。当基础模型直接长在分析引擎里，数据平台开始承担"分析与预测同栈"的角色，也会改变企业为时序建模单独采购工具与算力的做法。

Product & Tech

VAST Data 与 DigitalOcean 扩大合作，把存储、数据库与向量检索合并成一层

来源： VAST Data
摘要： VAST Data 宣布扩大与 DigitalOcean 的战略合作，把 VAST AI OS 部署进 DigitalOcean 的 AI 原生云。DigitalOcean 提供托管的 Agent Data Services，代理与 AI 应用在其中读写上下文，数据落地即建索引、可按语义检索，并落在单一租户隔离目录内。
对数据平台的影响： 官方称这一形态取消了独立的向量数据库与 ETL 管道，由内置治理控制每个代理的读写权限。若成立，会把"对象存储＋向量库＋管道"的三件套压缩成一层底座，改变智能体数据层的架构选型与成本结构。

AWS Glue Data Quality 新增结果查询 API

来源： AWS SDK for Go v2 发版说明
摘要： AWS 在 Glue 服务 SDK 中新增数据质量结果查询接口 GetDataQualityResultV2、BatchGetDataQualityResultV2 与 ListDataQualityResultsV2，可返回来自任意受支持数据处理引擎发布的数据质量评估结果。
对数据平台的影响： 数据质量结果不再绑定单一引擎，多引擎管道的质量结论可以统一取回与比对，为跨引擎的数据治理与流水线门禁提供统一的数据面。

火山引擎 DataLeap 更新 LeapAgent One 与数据探索 Skill

来源： 火山引擎功能发布记录
摘要： 火山引擎 DataLeap 发布记录显示，LeapAgent One 新增会话分享链接、支持直接打开与预览 CSV/TSV、升级运维诊断与健康检查，并新增 dataleap-data-explorer、dataleap-requirement-to-code 两个 Skill，同时上线资源包计费。
对数据平台的影响： 数据开发平台正在把"数据探索"和"需求转码"拆成可复用的 Skill，并叠加按量计费，说明国内厂商开始把智能体能力做成平台内的标准工序，而非附带的聊天入口。

火山引擎 EMR AI 助手接入豆包工作平台

来源： 火山引擎 EMR AI 助手介绍
摘要： 火山引擎开源大数据平台 EMR 的 AI 助手以连接器形式上架豆包工作平台，用户可用自然语言诊断 Spark 作业，结果覆盖任务状态、资源使用、执行耗时、失败信息与优化建议，文中称任务耗时从 53 秒压缩至 10 秒。
对数据平台的影响： 大数据诊断从控制台走向通用办公入口，专业诊断能力被包装成办公软件里的一个插件。数据平台的触达面因此从数据团队扩展到普通办公用户，跨系统排查的成本也被转移到平台侧。

腾讯云 TDSQL-C 新架构推出分支能力，为智能体提供数据沙箱

来源： 腾讯云数据库产品文章
摘要： 腾讯云 TDSQL-C MySQL 版新架构 2.0 推出分支能力（Branch），基于读写快照与共享数据基线快速创建可读写实例，克隆目标控制在 1 分钟内，用于 Agent Sandbox 与 AI Coding 验证。
对数据平台的影响： 智能体改 SQL、调索引、修数据都需要接近生产的数据环境。把"一键克隆出隔离副本"做成新架构面向 AI 的首个能力，等于用存储快照解决智能体试错的污染问题，方向与 Databricks 的数据库分支一致。

Views & Research

Atlassian CEO Mike Cannon-Brookes：企业上下文图谱才是护城河

来源： 20VC 播客（2026-10-12）
核心观点： Cannon-Brookes 在 20VC 访谈中称"无头化是无脑下注"：智能体不会替代所有界面，价值会转向可信工作流与新鲜的企业上下文。Atlassian 的核心押注不是模型也不是聊天机器人，而是持续更新的团队图谱，他并称多数"自研模型"只是对他人模型的微调。
映射到数据平台的判断： 他把组织上下文定义为需要保持新鲜的事实索引，而非囤积的原始数据，这与数据平台语境里的语义层、元数据与上下文工程同构；也提示评估数据平台时要看上下文能否被智能体按权限取用，而不只看存得多寡。
