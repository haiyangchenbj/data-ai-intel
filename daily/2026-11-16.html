Databricks 发布 OpenAI 工具企业落地指南，Codex 调用统一走 Unity Gateway

来源： Databricks 官方博客
摘要： Databricks 于 11 月 13 日发布企业采用指南，给出在受治理数据上使用 OpenAI 工具的三条路径：业务用户经 ChatGPT 的 Genie 插件按企业指标定义查询，答案回链数据源且权限沿用既有边界；Codex 请求经 Unity Gateway 路由，OpenAI 密钥留在网关、每次调用留日志、管理者可按团队设预算（网关已 GA，部分配套工具仍为 Beta）；自定义 Agent 经 Model Serving 部署在受治理数据旁，无需外部 API Key。合作本体为 2025 年 9 月官宣的多年协议，本篇将其落成可执行的部署模式。
为什么对数据平台重要： 模型调用的密钥管理、审计日志与预算控制正在向数据平台侧收敛，Unity Gateway 这类控制面成为数据平台承接企业 AI 的核心组件；「模型网关＋治理」预计将成为各平台的标配能力与采购评估项，Snowflake 的 Cortex AI Gateway 走的是同一方向。

Google Cloud 把 Agent 可观测性与治理压进 BigQuery 与 Looker

来源： Google Cloud 官方文档 BigQuery Agent Analytics
摘要： Google Cloud 于 11 月 13 日在官方博客宣布扩展 Google Data Cloud 的 Agent 可观测性与评估能力：一方 Agent 零配置发送遥测，用 ADK 或 LangGraph 构建的自定义 Agent 经一行 SDK 接入；对话日志（GA）经 Storage Write API 写入客户自有的 agent_events 表，继承 IAM、CMEK 与 VPC Service Controls；知识源带行级安全、策略标签或动态脱敏时，记录侧 fail-closed 跳过、执行侧 fail-open 不中断会话。成本侧新增按日 token 配额（Preview，可按项目/用户/Agent 强制），配合 BigQuery 按查询的字节扫描上限，在计费发生前拦截超大查询。
为什么对数据平台重要： Agent 遥测的归属地被明确设计为客户自有 BigQuery 表而非第三方面板，隐私检查、成本限额与评估结果直接复用数仓的治理与计费模型；轨迹、token 消耗与评测分数正在成为数仓里的新数据品类，数据平台成为 AI 运营数据的默认存放与治理层。
