🔥 今日最重要的3个变化

  1. 数据平台的竞争重心，从功能数量转向能否管住智能体的动作
  2. 交互入口持续上移，取数、试用与采购都开始走对话
  3. 开放表格式的摄取边界继续外扩，变更日志开始统一进管道
总判断：本期主线是智能体从问答走向执行。数据平台把代码执行、外部工具调用与采购入口逐步交给智能体，同时用沙箱、权限继承和目录把边界收住；湖仓侧继续把开放表格式的变更日志纳入统一摄取。厂商的比拼已从功能多少，移向能否让智能体的动作可管、可查。

Databricks 让 Genie One 在隔离沙箱中执行代码，权限仍沿用调用者

来源：Databricks 官方发布说明：AI/BI and Genie One release notes 2026
摘要： 10 月 9 日的发布说明显示，Genie One 现可在安全隔离的沙箱中运行代码，以承接 SQL 之外的分析任务。代码按调用者身份、沿用其已有权限执行，Databricks 明确 Unity Catalog 的治理与数据访问控制继续适用。发布说明同时提示更新为分批推送，账号可能滞后一周以上才生效。
为什么对数据平台重要： 面向业务用户的智能体能力从"查数"扩到"算数"，平台要同时给出两条保证：沙箱解决执行隔离，权限继承解决治理归属。任一条缺失，Agent 场景就只能停在试用阶段，无法进入受监管数据。值得追问的是沙箱内的资源上限与出网策略如何设定，以及执行产物是否同样纳入目录与血缘。

Snowflake 把数据市场发现交给对话式智能体，从检索走向采购

来源：Snowflake 官方发布说明：Agentic Marketplace Discovery (Public Preview)
摘要： 10 月 9 日，Snowflake 宣布 Agentic Marketplace Discovery 进入公开预览。用户可在 Snowsight 的 Marketplace Discover 页切换"智能体发现"与"市场搜索"，用自然语言描述需求，由 CoCo 找出并比较匹配的列表。在列表与角色权限允许的范围内，用户可从对话中查看详情、安装、发起试用或提交销售请求。
为什么对数据平台重要： 数据产品的发现与试用被移进对话入口，市场页从检索工具变成智能体编排的界面。对平台方，这意味着列表元数据、权限模型与试用开通流程都要能被机器直接调用，而不只是渲染给人看。可观察的抓手是：安装与试用这类带副作用动作由谁确认，以及智能体在比较列表时依据的是厂商自述还是可核验的运行数据。

湖仓开始直接摄取开放表格式的变更日志

来源：Google Cloud 官方发布说明：BigQuery release notes
摘要： 10 月 9 日的 BigQuery 发布说明称，Lakehouse 现支持从 Delta Lake 与 Apache Iceberg 表做变更数据捕获摄取，状态为预览。用户可用 Dataflow 批处理作业同步 Delta Lake 的插入、更新、删除日志，或用批处理与流式作业同步 Apache Iceberg 的日志，写入 Lakehouse 的 Iceberg 表。
为什么对数据平台重要： 变更日志此前分散在各表格式的私有能力里，现在被拉进统一摄取通道。对多引擎、多表格式并存的企业，增量同步不必再为每种格式各写一条管道，摄取层开始承担格式归一。这同时是一道边界题：格式归一发生在摄取层，意味着上游表格式的差异被吸收，但也把一致性判断从源系统移交给了湖仓侧，需要确认删除与更新事件在跨引擎读取时的可见性保证。

Product & Tech

Apache Flink CDC 3.7.0 发布，把模型调用接进变更数据捕获管道

来源：Apache Flink 官方发布公告：Apache Flink CDC 3.7.0 Release Announcement
摘要： 10 月 10 日，Apache Flink 社区发布 Flink CDC 3.7.0。该版本引入可插拔的 AI 模型客户端 API 与 OpenAI 兼容客户端，在 YAML Transform 中提供补全、分类、翻译、摘要、信息抽取、脱敏、文本与图像嵌入等内置函数，并新增实验性的有序异步执行。同时新增 SQL Server 与 Apache Fluss Pipeline 源连接器，支持在 Pipeline YAML 中直接定义 Python UDF，Paimon 依赖升级至 2.0.0、Fluss 升级至 1.0.0。
对数据平台的影响： 变更数据捕获管道开始承担轻量 AI 变换，模型调用被当作一种表达式放进流式作业。这对成本的直接影响是：原本要在下游单独跑的清洗与打标，可以在管道内完成，但代价是管道运行时长与模型调用量绑定。新增 Fluss 源连接器与 Paimon 依赖升级，说明 CDC 正在向湖流一体的目标端靠拢。

DuckDB 的 CLI 加了 agent mode，按机器读者的方式输出

来源：DuckDB 官方博客：Agent Mode in the DuckDB CLI
摘要： 10 月 9 日，DuckDB 团队介绍随 DuckDB v2.0 发布的 CLI agent mode。当命令行检测到环境变量表明调用者是编码智能体、且输出不是终端时，CLI 改用紧凑 Markdown 表格、把错误输出为 JSON、对超长查询先给出预估行数、并在结果被截断时显式标注。官方实验由 Claude Code 回答 22 道 TPC-H 题目（规模因子 100），agent mode 与普通模式各跑三次，132 次全部正确，模型读到的输出从 123.6k token 降到 50.8k token，减少 59%；官方同时说明这部分节省只占总输入的约 0.5%。
对数据平台的影响： 数据工具的默认输出开始按"机器读者"而非"终端用户"设计：省略对齐填充、显式声明截断、提前给出查询代价。这类改动不改变引擎能力，却直接决定智能体在数据管道里跑得准不准、贵不贵。官方主动标注节省幅度占总输入比例很低，也提示一个易被忽略的事实：真正吃掉 token 的往往不是查询结果，而是每一轮重复读入的上下文。

Snowflake 托管 Iceberg 表备份转正，术语从快照改为备份

来源：Snowflake 官方发布说明：Backups for disaster recovery and immutable storage
摘要： 10 月 9 日，Snowflake 宣布托管 Apache Iceberg 表的备份功能正式可用，覆盖面向灾难恢复与不可变存储的备份策略、备份集与保留锁，支持手动与定时备份、按对象类型恢复，并提供信息模式、账户用量与组织用量三类视图。官方同时把该能力的术语从 snapshot 统一改为 backup，旧的 SNAPSHOT 命令、视图与权限保留但标记为弃用，并计划在未来版本移除。
对数据平台的影响： 开放表格式的灾备与合规保留，此前多由存储侧或第三方工具承担，现在被收进平台原生命令体系。术语从"快照"换成"备份"，让跨引擎沟通时的语义更贴近企业既有的备份与合规流程。对买方的实际影响是双重的：一方面保留锁与法律保留这类合规动作可以在平台内完成，另一方面命令与视图的重命名会传导到既有脚本，升级前需要清点对弃用名称的依赖。

Snowflake 把标签与数据保护策略搬上控制台，标签覆盖率可视化

来源：Snowflake 官方发布说明：Snowsight interface for tags and data protection policies
摘要： 10 月 9 日，Snowflake 宣布通过 Snowsight 界面管理标签与数据保护策略正式可用，需企业版及以上。用户可在治理与安全下的标签与策略页创建标签，并用面板查看各对象类型的标签覆盖率；数据保护策略同样支持在界面中创建与维护，可查看策略态势、策略列表，以及受保护的表、视图与列。
对数据平台的影响： 标签与策略从"必须写 SQL 才能配"变成控制台可视操作，治理的落地门槛下降。覆盖率面板把标签覆盖变成可度量的指标，也让治理成效第一次有了能逐项核对的界面口径。需要留意的是，界面简化的是配置动作，不是判定逻辑：策略的实际生效范围、继承关系与冲突处理仍取决于底层模型，控制台只是把它显性化。

BigQuery 数据工程 Agent 在东京区域上线，并支持新一代小模型

来源：Google Cloud 官方发布说明：BigQuery release notes
摘要： 10 月 9 日的 BigQuery 发布说明称，数据工程 Agent 已在 asia-northeast1（东京）区域端点上线，并支持 gemini-3.5-flash 模型，状态为正式可用。此前的 10 月 2 日说明中，该能力已支持另一款模型并覆盖 us、eu 与 global 多区域端点。
对数据平台的影响： 数据工程 Agent 的可选区域与模型继续扩容，对数据驻留要求较高、需要把处理留在本地的企业，可用范围从少数多区域端点扩展到东京这样的单一区域。区域与模型组合按端点分批放量，意味着选型时的实际可用性取决于所在区域，而不是产品整体是否宣布可用。对采购评估，落地区的合规资质与模型版本是否同步更新，是比功能清单更需要逐项确认的部分。

火山引擎云数据库 TiDB 版开启公测，交易与向量检索共用一份数据

来源：字节跳动数据库官方账号（掘金）：火山引擎「云数据库 TiDB 版」正式开启公测
摘要： 火山引擎宣布云数据库 TiDB 版正式开启公测。该产品基于平凯星辰开源的 HTAP 数据库 TiDB 打造，全托管云原生，兼容 MySQL 协议生态，采用存算分离架构支持在线水平扩缩容，提供可视化控制台完成扩缩容、备份恢复与监控告警。官方称一套系统可同时支撑在线交易、实时分析与向量检索，交易与分析共用一份数据，并面向 RAG、Agent 平台、智能搜索等场景提供支撑，配套 30 天备份留存与任意时间点恢复。
对数据平台的影响： 国内云厂商把开源 HTAP 数据库做成托管服务，卖点从"替代单机 MySQL"转向"交易、分析与向量检索共用一份数据"。向量检索与 HTAP 合流，说明国产数据库在补 AI 原生场景的底座位置，也把选型问题从"要不要单独上向量库"改成了"能不能共用一份数据"。实际成色取决于存算分离下的向量索引性能与事务一致性如何兼得，这两项通常互相牵制。

Views & Research

镜舟科技 CEO 孙文现：数据平台的下一步是让 AI 正确理解数据

来源：中华网科技：从 StarRocks 到 MIP：数据平台的下一步是「理解」（署名文章，作者为镜舟科技 CEO 孙文现）
核心观点： 孙文现在署名文章中提出，StarRocks 解决的是数据如何被更快查询，接下来的 MIP 要解决的是企业数据如何被 AI 正确理解和使用。他把客户反复提出的问题归纳为三类：AI 怎样使用已有数据、文档与结构化数据能否一起分析；同一个指标怎样让 AI 采用适合当前任务的定义；不同角色能看哪些数据，以及答案出现偏差后能否找到原因。他称 MIP 的方向正是在这些跨客户的讨论中逐渐形成的。
映射到数据平台的判断： 引擎厂商开始把"语义与可核验"当作下一层竞争面：查询性能是入场券，业务口径的明确归属、按角色的数据可见性、以及答案可追溯，才是智能体直接消费数据时的真正门槛。这与此前厂商把语义层摆到目录位置的动向一致，但这次是来自国内引擎厂商的第一人称表述。可继续观察的是 MIP 是否会开放为跨平台规范，还是停留在自家产品内的能力集合。

来源：腾讯新闻（原稿：CIO Dive）：微软谷歌支持 Apache Ossie，推进 AI 平台互操作性
为什么值得继续看： 该规范用 JSON 与 YAML 描述数据集、字段、关系、指标与 AI 上下文，目标是让语义模型在 Snowflake、Databricks、Tableau、ThoughtSpot 等平台之间迁移，已有超过 60 家公司参与，包括 Databricks、Informatica、英伟达、甲骨文、Salesforce 与 Snowflake。微软称会开发 Power BI 语义模型与该规范的双向转换器，并推动把 DAX 纳入其认可的查询语言；Google 方面确认正在加入，但未披露具体贡献。项目仍处 Apache 孵化阶段，规范版本标注为开发草案，分析人士指出行列级安全、访问策略与认证状态尚未作为一等元素纳入，跨平台仍需重复配置；同时指出移植的是定义，围绕定义的行为仍留在各平台。
