趋势

月度趋势分析

趋势一：Agent 数据平台从模型连接走向治理与运行时（高可信）

核心判断：9 月的公开动作显示，Agent 与数据平台的集成焦点从"能否连上模型"转向凭据托管、身份注册、会话治理和成本观测；相关能力多数为 GA 或 Preview，生产验证仍集中早期。
日期厂商/项目事件状态与治理维度
09-11OpenAIChatGPT Work 上线 Data agent对话界面直接调用企业语义层数据。
09-23DatabricksGenie One MCP 正式可用GA；以 Unity Gateway 托管服务对外治理 MCP 调用。
09-22Google CloudBigQuery 数据代理接入 Gemini EnterpriseAgent Registry 托管智能体凭据与身份。
09-24AivenRuntime 与 DataHub 正式可用智能体运行位置与数据地图一起交付。
09-29MongoDBAtlas Agent EnginePublic Preview；面向 Agent 生产化免新建技术栈。

OpenAI 把 Data agent 放进通用工作界面，Databricks 和 Google Cloud 分别以 MCP 网关和 Agent Registry 治理调用与凭据，MongoDB 与 Aiven 把 Agent 运行时和数据地图打包为独立产品层，Microsoft Fabric 则在 9 月将 Fabric IQ MCP Server、Core MCP Server 与 Data-agent MCP 任务批量转入 GA。方向一致：谁托管身份、谁记录审计、谁归因成本。

这些能力的治理口径（委托链路、工具调用范围、成本归因粒度）尚未有跨厂商统一标准，采购评估需逐项对照。

评估要点：
- Agent 凭据托管、审计记录与任务级权限是否可追溯、可撤销。
- MCP/注册表类能力的多引擎覆盖范围与锁定程度。
- GA 与 Preview 能力在生产控制面中的责任边界差异。

趋势二：开放湖仓成为默认数据接口（高可信）

核心判断：9 月 AWS、Databricks、Snowflake、Google、Starburst 的动作显示，Iceberg 已从存储格式上升为查询、共享与治理的默认接口，开放湖仓与运营数据库的边界开始融合。
日期厂商/项目事件已公开能力

09-11Apache Icebergread restrictions 与 catalog labels 规范治理语义写入开放表格式规范层。
09-14DatabricksOpenSharing 外部 Iceberg 表共享 GA外部 Iceberg 表与 schema 共享正式可用。

月内三条线同时推进：规范层（Iceberg 治理规范、1.12 预览）、引擎层（Redshift、Snowflake 分区演进、Starburst 增量刷新）和融合层（Aurora 直接查询数据湖、BigQuery 连续查询输出写入 Iceberg managed tables、S3 Tables 支持 Iceberg v3 数据类型）。开放格式覆盖了从事务数据库到对象存储的完整链路。

格式开放降低锁定，不自动消除迁移与运维成本；跨引擎查询的性能与计费口径需按各厂商文档分别评估。

评估要点：
- 联合查询类能力的计费模型（计算资源与 S3 请求费用）与性能边界。
- Catalog、权限模型与治理规范在各引擎间的一致性。
- Iceberg 1.12 因许可问题推迟发版对升级节奏的影响。

核心判断：多家数据库厂商开始把 Agent 会话状态、记忆、沙箱与秒级弹性下沉为数据库原生能力；产品形态各异，多数处于 Preview 或发布初期，生产案例有限。

Google 的沙箱实例解决 Agent 任务的短生命周期隔离，华为云把跨会话记忆上移为平台组件，Snowflake 压缩会话表示以控制上下文成本。三者共同指向：Agent 工作负载的状态管理正在成为数据库的新设计约束。

阿里云在云栖大会期间提出的 Context Engine 属于概念口径，产品化状态待官方文档确认，此处仅作信号记录。

评估要点：
- 会话状态、记忆与分支数据的生命周期管理和回收机制。
- 沙箱实例的身份隔离与中心数据层之间的权限边界。
- Preview 阶段能力在 SLA、地域覆盖与计费上的限制。

趋势四：国内数据要素制度从文件走向凭证与行动（高可信）

核心判断：9 月国内数据要素政策从制度文件进入执行载体：统一登记系统上线、首批凭证发放、行业攻坚行动启动，确权、流通与资产化路径开始有了可核验的操作层。
日期机构事件已公开信息
09-01国家数据局四项新举措数据标注试点、词元商业模式、央国企数据开放。
09-09国家数据局局长署名文章数据要素市场化与全国一体化数据市场建设加速。
09-14国家数据局数据产权登记服务系统上线全国统一登记制度落地。
09-21国家数据局首批 56 家主体取得登记凭证凭证可用于交易、融资担保、作价入股等场景。
09-23国家数据局十大行业数据资源开发利用攻坚行动聚焦行业数据开发利用难点。

登记凭证把数据持有权与经营权变成可核验的法律操作对象，这是制度供给与市场交易之间的关键一步。凭证可支持的交易、融资担保与作价入股属于制度用途，尚未等同普遍形成的数据交易市场。

同期工信部《"人工智能+软件"专项行动实施方案》（文件落款 9/2、新闻发布会 9/11）提出 2028、2030 年目标，属政策规划口径，不是已实现成果。

评估要点：
- 凭证跨区域互认、质押融资与入表的实际落地案例。
- 登记审查维度（三维度审查与负面清单）对企业数据资产化的影响。
- 攻坚行动从政策到采购需求的转化速度。

趋势五：检索与上下文成为数据平台内置能力（中可信）

核心判断：混合检索、自适应检索与上下文管理开始从外挂组件转为数据平台内置件；检索层的竞争从"能不能搜"转向延迟、成本与治理。
日期厂商/项目事件状态

09-03阿里云ES AI 引擎版发布无状态多租户架构；"亿级 Agent 检索"为厂商口径。
09-10Databricks自适应检索模型检索层成为平台内置件；性能数字为厂商披露。

09-22Google CloudAlloyDB 列式引擎作向量索引内存缓存GA。

数据库内置 BM25 与向量缓存压缩了"数据库+独立检索引擎"的架构分层，检索精度与延迟数字均来自厂商披露、未经独立基准验证。dbt 的 Context Layer 则把上下文治理前移到语义层。

评估要点：
- 内置检索与独立检索引擎在规模、成本与更新时效上的差距。
- 语义层上下文与企业现有指标口径的兼容成本。
- 按量计费模式下 Agent 高频检索的实际成本曲线。
